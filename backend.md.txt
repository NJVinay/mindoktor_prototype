--- TRIAGE SESSION ---

POST /api/v1/triage/session
  Body: { body_zone?: string }
  Response: { session_token: UUID }
  Creates empty triage_sessions row, returns token

PUT /api/v1/triage/session/:token/answer
  Body: { question_id: "q1"|"q2"|"q3"|"q4", answer: string }
  Validate: question_id in enum, answer in allowed values
  Action: upsert answer into triage_sessions.answers JSONB
  Response: { session_token, answers_so_far, next_question_id | null }

POST /api/v1/triage/session/:token/resolve
  Triggered: when all 4 answers are submitted
  Action:
    1. Run rule-based scoring (see TRIAGE ENGINE below)
    2. If confidence_score < 0.6: call GPT fallback
    3. Write predicted_category_id, predicted_conditions,
       confidence_score, gpt_reasoning to DB
    4. Run doctor matching (see DOCTOR MATCHING below)
    5. Write recommended_doctor_id to DB
    6. Mark completed_at = now()
  Response:
    {
      predicted_conditions: [
        { slug, name_en, category_key, confidence: float }
      ],
      primary_condition: { slug, name_en, body_zones },
      category: { key, name_en, icon_name },
      confidence_score: float,
      recommended_doctor: {
        id, name, specialty, avg_rating,
        response_time_hours, avatar_url
      },
      gpt_reasoning: string | null,
      emergency: boolean
    }

GET /api/v1/triage/session/:token
  Response: full session object including result

--- DOCTOR MATCHING ---

GET /api/v1/doctors/match
  Query params: category_key, body_zone, condition_slug
  Response: top 3 available doctors sorted by:
    1. condition_tags overlap (most matching first)

==============================================================
TRIAGE ENGINE (triage/engine.ts or triage/engine.py)
==============================================================

Build a deterministic scoring function:
  Input: TriageAnswers { q1, q2, q3, q4, body_zone? }
  Output: ScoringResult {
    category_key: string,
    condition_slugs: string[],  // top 3
    confidence_score: number,   // 0.0–1.0
    is_emergency: boolean
  }

RULE MATRIX — map answer combinations to categories:

  q2 (location)         → primary category
  ─────────────────────────────────────────────
  head/face/throat      → respiratory-cold
  chest/breathing       → respiratory-cold
  stomach/digestion     → chronic-internal
  skin/visible change   → skin-body
  mental/mood           → mental-lifestyle
  muscles/joints/back   → chronic-internal
  private/sexual        → womens-sexual
  not sure              → → GPT fallback

  q3 (intensity) modifier:
  severe + q1 = today   → is_emergency consideration
  emergency             → is_emergency = true, confidence = 1.0

  q1 (duration) modifier:
  ongoing/recurring + q4 = diagnosed condition
    → boosts chronic conditions in ranking

  q4 (history) modifier:
  first time → acute conditions ranked first
  recurring  → chronic conditions ranked first
  on medication → cross-check with condition.tags has "chronic"

CONFIDENCE SCORING:
  base_score = 0.5
  + 0.2 if body_zone matches q2 location
  + 0.15 if q1 duration is consistent with condition.typical_duration
  + 0.1 if q4 history is consistent
  + 0.05 if q3 intensity is within condition.severity_range
  If no body_zone provided: base_score = 0.35

EMERGENCY LOGIC:
  if q3 == "emergency":
    return { is_emergency: true, category: null, conditions: [] }
    Response includes: emergency_message, emergency_number: "112"
    Do NOT call GPT for emergency cases

GPT FALLBACK (if confidence_score < 0.6 OR q2 == "not sure"):
  Call OpenAI Chat Completions:
  System prompt:
    "You are a Swedish primary care triage assistant.
    Given a patient's symptom answers, return a JSON object:
    { category_key, top_conditions: [slug1, slug2, slug3],
      reasoning: string (max 2 sentences),
      confidence: float }
    Use ONLY categories and slugs from the provided list.
    Never diagnose — only suggest appropriate care category."
  User prompt:
    "Duration: {q1}. Location: {q2}. Intensity: {q3}.
    History: {q4}. Body zone from model: {body_zone|none}.
    Available categories: {category_keys_json}.
    Available conditions: {condition_slugs_json}."
  Parse response JSON → merge with rule-based result
  Use higher confidence score of the two

==============================================================
AUTOCOMPLETE SERVICE
==============================================================

File: services/autocomplete.ts (or autocomplete.py)

Function: searchConditions(query, lang, limit=5)
  1. Normalize input: lowercase, strip diacritics
  2. Check Redis cache: GET autocomplete:{lang}:{query}
  3. If cache miss: run PostgreSQL query:
     SELECT c.slug, c.name_sv, c.name_en,
            cat.key as category_key,
            c.body_zones,
            similarity(si.term, $1) as score
     FROM search_index si
     JOIN conditions c ON si.condition_id = c.id
     JOIN categories cat ON c.category_id = cat.id
     WHERE si.lang = $2
       AND si.term % $1
     ORDER BY score DESC, si.weight DESC
     LIMIT $3;
  4. Cache result: SET autocomplete:{lang}:{query} TTL=1800
  5. Return array of SearchResult objects

Index to build:
  CREATE INDEX search_index_term_trgm
  ON search_index USING GIN (term gin_trgm_ops);
